Live webcam demo

From visual change to a description

The goal is to update context when a scene changes without asking a vision-language model to describe every sampled frame. In its default hybrid mode, the demo combines a visual change gate with a small session memory of previous descriptions.

How it works

  1. Separate the scene. MediaPipe creates person and background views from each sampled webcam frame. CLIP encodes those views and the full frame.
  2. Detect change. The person and background embeddings are each compared with their stored reference. When either cosine distance exceeds the gate threshold, the affected reference is refreshed and the demo emits a trigger.
  3. Check previous descriptions. The first frame is described by LLaVA. For later triggers, CLIP compares the current full-frame embedding with embeddings of descriptions stored during this run. If a match passes the similarity and margin thresholds, the description is reused.
  4. Describe a new view. When there is no suitable match, LLaVA generates an open-ended description from the full frame. Eligible descriptions are added to memory for later comparisons; the memory starts empty on each run.

The default change threshold is 0.10. Reuse requires at least two distinct stored descriptions, a best similarity of at least 0.30, and a margin of at least 0.04 over the next candidate. These are starting values rather than calibrated confidence scores.

What the interface shows

The plot displays person and background distances to their respective references at each sample, along with the threshold, trigger points and reference resets. The model panels show the segmentation views, current distances, memory decision, LLaVA calls and description reuses. Camera display and inference run separately; when inference falls behind, newer frames replace queued ones.

Scope and next step

Descriptions are inferred from individual images and can miss or confuse visually similar activities. A controlled comparison on recorded sequences is needed to measure response time, missed changes and model-call reduction.
